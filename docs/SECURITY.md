# 边界与可测试的安全约束

- 仅虚构政策、模拟数据、loopback 服务；没有真实退款/支付接口。
- 随机开发凭据在外部运行目录 auth.json 生成并保存，服务端映射 alice/bob/admin。请求体 user_id 被 extra=forbid 拒绝。开发凭据不等于生产登录。
- 读订单严格匹配 owner，不能沿用原 RAG 的 demo 用户归属豁免。角色工具名单没有写入函数；工具参数绑定当前订单及用户声明。资格结果不取决于模型说“允许”。
- Cookie HttpOnly + SameSite Strict；带 Cookie 的跨源写请求被拒绝。无 CORS 放开；不将开发 token 放 URL。仅管理员可在 demo/test 注入故障和状态变化。
- 明确确认绑定 proposal_id + version，动作参数只能来自 DB。修改使旧方案失效，拒绝不写业务，状态变化要求重新确认。重复确认返回相同记录。
- 外部 RAG 仅只读且只接受本地政策文本/版本完全匹配的证据；不接受未经核实的远程引用。文档内容作为资料而不是工具权限指令。
- LangSmith/LangChain tracing 显式关闭；没有默认上传日志。启用 model/RAG 时仅向主动配置的接口发请求。密钥只从环境读取，HTTP 失败只记录错误类型。
- 运行目录禁止放入公开项目。公开审计检查全部文件、二进制、链接、个人路径和凭据模式，不依赖 .gitignore。

已知限制：单进程、开发认证、普通本地文件权限；持有 admin 凭据能改变模拟数据。没有多租户生产认证、速率限制、恶意大规模流量防护或生产数据保留策略。此范围不包含生产上线安全承诺。
