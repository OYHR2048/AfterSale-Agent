# AfterSale-Agent 实现规格

范围：虚构商店、本地模拟订单，三个固定角色，单进程。申请受理不代表退款到账。

交付顺序：单 Agent 闭环 → Supervisor 与两个独立工具循环 → 异常/确认/事务 → SQLite checkpoint 恢复 → 同源页面/SSE → 确定性测试与 10 dev/30 test 比较。公开交付检查完成后才制作个人资料。

身份由服务端开发凭据映射；请求体不接受 user_id。Agent 只有只读工具。执行模块校验订单、方案版本、有效期、政策指纹、库存、确认，并在一个事务内保存业务记录和结果。每个任务最多一笔业务记录。

演示模式是规则决策替身；test 是脚本决策替身；model 是明确启用的兼容 Chat Completions JSON 决策。没有付费预算，本次只运行离线验证。

停止条件：全局步骤预算、专业循环预算、重复委派预算、工具超时/重试预算、用户拒绝、业务不可行、外部失败。所有状态及事件落入 SQLite，恢复使用相同 thread_id。
